# Seedtrail in a plugin host

Use the current user request, project instructions and available tools to choose the next useful procedure. guide-product is the entry for an idea or resumption; the other ten procedures can be used directly for their specific task.

## Three supported contexts

- Existing repository: inspect its instructions, product sources and current changes. Adopt the procedure through reading; preserve its existing documentation and tracking. Missing .kit is not an error. Do not install or migrate a structure merely to use a procedure.
- Conversation or supplied documents: produce the requested analysis, specification, decisions or handoff using accessible sources. Use the user's language. If persistent artifacts are available, save useful outputs there; otherwise return them in chat and explain continuity limits. Do not claim local inspection, execution, research or persistent state without the corresponding tools and evidence.
- New local project: initialize only when the user asks for a new Seedtrail instance. PowerShell 7.2+ is needed only for the optional helpers. Read library/scripts/init-project.ps1 before using it; its Destination must be a new writable directory outside this library. It does not merge an existing project. Resolve helper paths from this reference, never from a developer-specific absolute path.

## References and actual product state

library/templates/.kit contains the method; library/templates/docs/product contains formats, not completed evidence. Procedural links in a portable skill point to bundled formats. References to .kit/project.json, docs/product, active_work and handoff in prose describe the user's instance only when one exists. Prefer the user's actual records over bundled examples.

When reading an original procedure via library/templates/.agents/skills, apply this same host adaptation. Cross-links inside that library stay relative to the preserved library layout. Do not change host settings, publish, contact people, buy services or spawn agents based on the presence of a procedure. User scope and host permissions govern actions.

## Continuity and quality

Select only procedures relevant to the requested outcome. Ask for decision-changing gaps; preserve hypotheses, user decisions, observed results and limits separately. Resume by reading current records and verifying interrupted actions before repeating them. Neither files nor script success prove market validation, semantic quality or a completed release.

## Data behavior of this build

The package contains no MCP server, network API, account system, analytics, payment integration or donation tool. It supplies instructions, templates and optional local scripts. Host tools may read files, access the web or execute code when the user's request requires them; their permissions and data handling remain those of the host and connected services. The author cannot inspect user projects through this package.

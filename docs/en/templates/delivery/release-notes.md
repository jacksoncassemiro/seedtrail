# Delivery notes and versions

Status: model; no published version or confirmed delivery recorded here.

Create when collecting changes for delivery. Record reader-relevant changes with version/baseline and ISO date YYYY-MM-DD. Do not dump commits or complete work histories. Kit version is not product version.

Implemented/verified changes may still be unavailable to their intended audience. Research/proposals are not launched features. Separate change dates from delivery dates.

## Confirmed deliveries

For each version/delivery: identity, date, audience/environment, recoverable base and included work/capabilities. Explain relevant incompatibility, migration, removals, risks/limits and consumer actions. Avoid empty categories. External publishing needs its own authorization.

Before consolidation, check actual availability, verification, dependencies and consumer documentation. Independently version capabilities/components only with independent contracts/distribution; normally record product versions and capability revisions/bases. Capability histories point to deliveries; rationale/proof remain in authoritative work/decisions.

When volume justifies it, separate per-version notes under delivery/releases/<version>.md, retaining an index here. Do not duplicate authoritative notes. Period lookup uses recorded dates; Markdown tables provide no automatic query engine.

This kit neither installs/runs these tools nor requires extra fragments per work item.

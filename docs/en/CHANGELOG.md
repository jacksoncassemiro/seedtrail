## Updating instances

The initializer refuses an existing destination. There is no automatic migration. Preserve project state in Git or an identified copy, compare old base, adapted file and new template, incorporate relevant changes and resolve material conflicts.

Preserve context, decisions, sources, code and results. Renaming updates indexes, links, instructions, consumers, tests and handoff. Remove identified duplicates; keep unique content and superseded decisions as product history. Product history is distinct from preliminary framework versions.

Record the version in .kit/project.json after checking the updated scope, adaptations, open issues and recovery method. The same version does not imply identical files. Do not overwrite a whole instance with the library.

# Assess feasibility

Read existing context, research and decisions. Use [problem/value](../../../docs/product/definition/problem-and-value.md), [feasibility](../../../docs/product/business/feasibility.md) and [capacity/costs/evolution](../../../docs/product/engineering/capacity-costs-and-evolution.md). Personal skills are not required.

- Define desired outcome, user, buyer if different, current alternative and benefit. Distinguish a coherent proposal from observed demand/payment. Explore channel/adoption barriers beyond features.
- Compare doing nothing, manual process, prototype/experiment and first implemented slice. MVP tests an explicit hypothesis; it need not be a complete product or contain the entire future vision.
- Gather only current decision-changing constraints: time, people/experience, investment and operating ceilings. Unknowns call for conditional scenarios and the next question, not invented resources or an immediate full budget.
- Separate discovery/prototyping, construction, hosting/operations, maintenance/support and acquisition costs. Ranges/estimates need methods/assumptions; current prices need dated sources. Token cost is not total cost. Do not invent CAC/LTV/revenue.
- Challenge desire, execution and distribution; compare risk, reversible cost, benefit and abandonment/review conditions. Use challenge-assumptions for material review when relevant.

Output: value proposition/MVP scope, justified comparison, known constraints, review conditions and relevant experiments/metrics. Update affected business/roadmap/questions; separate recommendation from user choice. Analysis does not authorize purchasing, spending or publication.

Use [experiments/MVP](../../../docs/product/definition/experiments-and-mvp.md) to define hypothesis, smallest test and decision rule before results; prototypes are not validated products.
